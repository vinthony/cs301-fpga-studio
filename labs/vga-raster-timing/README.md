# VGA扫描与同步 · 两个共同像素时钟下的十位计数器

这是GBU-CS301中纯色组合模式的可运行Verilog参考，直接复用已验证的RasterCounter。输入`clk`已经是像素时钟；工程没有生成或分频时钟。

## 从网页走到电路

- 横计数X：0…799，每个使能像素边沿加一，终值回0。
- 纵计数Y：0…520，**仅在边沿前X=799且enable=1时**加一，终值回0。
- 两者在同一个像素时钟上升沿同时保存；没有用HS作第二个派生时钟。
- 同步reset优先于enable清零两个计数器。上电值未指定，先提交有效reset边沿。
- `hs`在X=656…751为0；`vs`在Y=490…491为0。
- `active`仅在X<640且Y<480有效；RGB组合输出可见时color，否则0。
- 地址在可见区为Y×640+X；消隐时address=0且address_valid=0，**不能把无效地址0当作正在读取首像素**。
- `next_x/next_y`是当前控制下的候选；reset/enable/color改变不冒充新的保存边沿。计数暂停时color仍可组合改变输出。

模式依据[Digilent Basys 3参考手册，第14页图14](https://digilent.com/reference/_media/basys3%3A%20basys3_rm.pdf)：640×480可见、800×521总扫描，25MHz像素时钟示例。纵后肩29行。本工程没有混用525行参数；仿真测试台节拍不代表实体器件可达到频率。

网页“从边界重新开始”是初始化，不是计数器跳转指令；硬件没有任意坐标装载口。网页没有同步复位输入，因此网页对照**不会声称验证了同名复位端口**：reset向量只为下一步网页测试建立起点；硬件reset本身由RTL检查。

## 独立复验

需要Python 3.11+、Icarus Verilog（iverilog、vvp）：

```sh
python3 verification/check.py
```

Python参考只保存一个0…416799的线性扫描索引，以整除/取余推导坐标；RTL使用两个独立保存计数器与行末使能，避免只把两计数器算法照抄进参考。

验证包括：全部416800个合法坐标×CE/RESET四组合；四个可见/消隐地址的全部4096种RGB颜色；两帧连续扫描及20000次固定种子控制。每个向量实际运行RTL，检查边沿前11个量及边沿后X/Y。穷举阶段由测试台注入任意合法起点；连续阶段承接上一次保存状态，没有逐拍强制赋值。

有网页源码时额外运行：

```sh
python3 verification/check.py --web-root /absolute/path/to/芯片细胞实验室
```

网页用同一批Python向量核对当前请求坐标/同步/有效/地址/RGB；reset=0时执行真实网页advance。`web.json`分列实际推进次数与reset初始化次数，避免把两者合并为硬件复位对照。未提供网页目录时不刷新旧web证据；`web-source-sha256.json`只证明打包时的源码版本。

## 波形与课堂观察

`evidence/sample.vcd`是实际RTL仿真，起点X=638、Y=489，随后2500个共同边沿包含暂停，可观察HS下降/上升、X行末回0、Y进位、VS进入及离开。样例仅首次由测试台建立起点，其余连续运行。对应输入/期望在sample-vectors.txt。波形文件用测试台2ns周期，**不是**25MHz或任何实体时序承诺。

课堂建议先看`x/y`，再看`line_enable`、`next_x/next_y`，最后同时看`hs/vs/active/rgb/address_valid/address`。尤其比较X=799→0时：纵计数参考的是边沿前的X，而不是已经变成0的X。

## 验证边界

本工程只覆盖合法扫描状态、纯色组合输出及行列控制。没有实现帧缓冲同步读、RGB/控制流水保存、PLL、完整VGA顶层引脚约束、综合布局布线、STA、模拟电压或真实显示器测试。没有证明任意非法X/Y的自恢复。功能仿真不能作为实体板完全一致的证据。
